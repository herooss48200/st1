# R32.2 Position Safety

- `TRADE_SIZE_USDT=50`: every NEW opening MARKET order is hard-capped to 50 USDT notional immediately before Binance submission.
- `MAX_POSITIONS=10`: global open-position cap is 10 in both `.env` and config fallback.
- `MAX_POSITIONS_PER_COIN=1` remains active.
- Opening MARKET orders now use a stable Binance `newClientOrderId`.
- If a MARKET POST returns an uncertain transport error, the bot queries Binance by `origClientOrderId`; it does **not** blindly POST the entry again. This prevents duplicate fills from retry logic.
- A second order-service safety gate checks live Binance open-position count and same-symbol exposure before every new opening MARKET order.

## Root cause found
The old `placeOrder()` retry loop retried opening MARKET POST requests after any error without a stable client order id or recovery lookup. If Binance filled the first request but the response was lost/timed out, the retry could fill a second MARKET order into the same one-way position. This explains live totals such as about 194.5 USDT (~2 x 97.25) and 147.3 USDT (~2 x 73.65), despite `TRADE_SIZE_USDT=100`.
